ssr-h 侧栏优化方案

针对 ssr-h 左侧栏（品牌 / 新会话 / 主导航 / 工作区 / 会话树 / 插件 / 页脚 共 7 段）的结构与视觉权重做一次收敛。目标不是换皮，是把「我现在在哪、下一步做什么」这两个问题在 264px 内一次说清。

依据：chat.html · layout.html · shell.css · pages.css · UED.md §5–§7 画板按 1:1 真实尺寸渲染
一 · 视觉权重倒置实心蓝「新会话」40px 全宽是侧栏最重的元素，比当前选中会话重得多 —— 视线第一落点是「新建」而不是「我在哪」。
二 · 同一个状态说了三遍「当前工作区」同时由 section 药丸（完整路径）、工作区树组头「当前」徽标、搜索占位符表达，占掉约 100px 却零新增信息。
三 · 密度与层级不足会话项两行实测约 56px（UED 记的 44 是估算，padding + 两个行高 + 间距把它撑大了），1000px 视口下一屏只有 9 条；标题还用 muted 色，7 段信息共用一根 1px 线。

为什么导航放底部

  • 「会话」不是一个目的地，而是这个应用本身 —— 它在导航里出现，反而暗示「还有别的会话页」。
  • 插件 / 供应商 / 概览 是低频设置面，底部是行业里已被训练出来的位置（Slack、Linear、Notion 侧栏左下角）。
  • 腾出的空间全部还给会话列表：配合行高收敛，一屏从 9 条到 15 条。
  • 底部与主题、连接状态同区，构成稳定的「系统区」，不再随会话数量上下浮动。

为什么删掉「工作区」独立分区

  • 工作区本质是「这批会话属于哪个目录」，它是列表的表头，不是列表外的一个控件。
  • 多个工作区时，组头（~/work/other · 2）已经承担切换职责；只有一个工作区时不该出现第二套表达。
  • 路径显示改为 目录名 + 父目录缩写（~/.a-da），完整路径放 title，不再从右侧截断把身份切掉。

4落地顺序

第 0 步（必须先做）· 抽单一真源

侧栏标记在 templates/chat.html 与 templates/layout.html 各有一份（26–98 行），改版必须改两遍。先抽 templates/partials/sidebar.html，两个外壳 {% include %}，再动样式。否则后面每一步都是双倍工作量 + 漂移风险。

第 1 步 · 结构（纯模板，不动 CSS 也能先看见效果）

  • 删 .ada-section（工作区药丸）整段，改为 .ada-ws-switch 一行式切换器。
  • 主导航 4 项拆两处：会话项移除（当前页即会话），其余三项下移到底部 .ada-nav--utility。
  • 会话行去掉 .ada-thread__meta 里的「N 项」，改挂 title 属性。

第 2 步 · 视觉（shell.css 局部重写）

  • .ada-thread：flex-direction: row、height: 32px、标题 13px/500 ink。
  • .ada-btn--primary 在侧栏内改用新的 .ada-btn--ghost 变体（描边）。
  • 删除 .ada-section 的 border-top，只保留列表上下两根；.ada-section--plugins 的独立滚动 max-height 一并去掉（插件已入底部区，无需自滚）。

第 3 步 · 交互（chat.js / app.js）

  • 搜索加计数字与空态；⌘K / Ctrl K 聚焦、Esc 清空。
  • 会话行 hover 的 ··· 菜单（复用现有 ada-modal.js，别新起一套）。
  • 折叠改为窄轨：is-sidebar-collapsed 不再 display:none，改宽度 264 → 56 + 文字渐隐。

第 4 步 · 响应式与验收

  • 补 @media (max-width: 1100px) 的 236px，与 UED §5.1 对齐。
  • 验收：1280/1440/960/860 无横向溢出；Light/Dark 两套下 32px 行的 hover 底可见；键盘可达（Tab 走完树、⌘K 可达搜索）；窄轨下所有 tooltip 有语义文本。

画板中的示例会话名取自 docs/preview.png 截图，仅用于对照；第二组「~/work/other」是演示多工作区形态的占位。
