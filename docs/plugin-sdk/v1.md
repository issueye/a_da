# 插件 SDK v1（冻结于 2026-10-08，随 TS 归档一起生效）

> 为什么有这份文档：插件的契约过去**只存在于 TypeScript 类型里**（`src/agent/plugins/types.ts`、
> `src/agent/tools/builtin-plugins/types.ts`、`src/agent/core/events.ts` 的 25 个钩子点位），
> 而真正执行插件的是 **Rust 沙箱**（`agent_core/src/plugins/sandbox.rs`）。
> TS 实现已归档到 [`archive/ts-legacy/`](../../archive/ts-legacy)，因此这里把契约**显式冻结**成语言中立的规范——
> 它是插件作者与 Rust 实现之间的唯一口径。
>
> 本文写的是 **v1 的真实能力**（含缺口），不是愿望清单。缺口都标了「v1 不支持」。

---

## 1. 插件文件形态：**单文件**

沙箱的执行方式（`agent_core/src/plugins/sandbox.rs:14-21`）：

1. `tokio::fs::read_to_string(plugin_path)` —— 读**一个文件**；
2. `transpile_ts_module(source, path)` —— oxc 只做 TypeScript 类型擦除；
3. 在 `PureTsRuntime`（进程内 JS 运行时）里求值。

**因此：插件必须是自包含的单文件**。`import './helper'`、`import '../x'` 这类相对路径
**没有模块解析器**（运行时只注入了 node 风格的基础模块，见 §5），会失败。
仓库里的内置插件（`archive/ts-legacy/src/agent/tools/builtin-plugins/**`）因为 `import '../../core/events'`
等深层依赖，**本来也无法被沙箱执行**——Rust 侧对它们有原生实现。

## 2. 导出形态：函数或对象

`export default` 必须是下面两者之一（`sandbox.rs:189-209`）：

```ts
// 形态 A：函数 —— 拿到注入 API，用 registerTool 声明工具
export default async function (api: PluginApi) {
  api.registerTool({
    name: 'hello',
    label: '打个招呼',
    description: '返回一句问候',
    parameters: { type: 'object', properties: { who: { type: 'string' } }, required: ['who'] },
    async execute(callId: string, args: { who: string }) {
      return `你好，${args.who}`
    },
  })
}

// 形态 B：对象 —— tools 数组里放工具对象或「接收 workspace 的工厂函数」
export default {
  tools: [
    (workspace: string) => ({
      name: 'hello',
      description: '返回一句问候',
      parameters: { type: 'object', properties: {} },
      async execute(args: Record<string, unknown>) {
        return { ok: true, output: `workspace=${workspace}` }
      },
    }),
  ],
}
```

`module.exports.default || module.exports` 被当作描述符（`sandbox.rs:165`）。

## 3. 注入 API（**仅形态 A 有**）

```ts
interface PluginApi {
  /** 写一行日志（当前落到沙箱的 console.log） */
  trace(msg: string): void
  /** 当前工作区绝对路径字符串 */
  workspace: string
  /** 注册一个工具；可多次调用 */
  registerTool(tool: PluginTool): void
  /** v1 不支持：当前是空实现，注册不会生效 */
  registerSkill(skill: unknown): void
  /** v1 不支持：当前是空实现，注册不会生效 */
  registerPrompt(prompt: unknown): void
}
```

对应实现见 `sandbox.rs:190-196`。**`registerSkill` / `registerPrompt` 是 no-op**——
声明它们是历史遗留，不要依赖；技能与提示词目前只能由核心侧（`skills/`、`prompts/`）管理。

**形态 B 拿不到注入 API**，工厂函数只接收 workspace 字符串（`sandbox.rs:206`）。

## 4. 工具对象与返回值契约

```ts
interface PluginTool {
  name: string            // 必填：模型看到的工具名
  label?: string          // 可选：展示名
  description?: string    // 可选：进系统提示词与工具表
  parameters?: object     // 可选：JSON Schema；缺省时核心按空对象处理
  execute: (callId: string, args: object) => Promise<PluginToolResult> | (args: object) => Promise<PluginToolResult>
}
```

**`execute` 的 arity 规则**（`sandbox.rs:229-237`）：参数个数为 1 时按 `execute(args)` 调用
（抛错则回退成 `execute('call_sandbox', args)` 再试一次）；否则按 `execute('call_sandbox', args)`。

**返回值映射**（`sandbox.rs:239-258`）：

| 插件返回 | 核心得到 |
|---|---|
| `string` | `{ ok: true, output: <字符串> }` |
| `{ ok?, output?, patch?, details?, terminate? }` | 原样取用（`ok` 缺省 true；`output` 非字符串则 `JSON.stringify`） |
| `null` / `undefined` | `{ ok: true, output: "" }` |
| 其它（数字/布尔…） | `{ ok: true, output: String(v) }` |
| 抛异常 | `{ ok: false, output: <错误信息> }` |

> 注意：工具**最终**回给模型的 `content` 由核心统一包成结构化回执
> （`status`/`ok`/`duration_ms`/`started_at`/`finished_at`/`data`/`output`，见
> `agent_core/src/runner/executor.rs:210-249` 与 AGENTS.md §18）。
> 插件只负责 `output`/`patch`/`details`，**不要自己拼回执 JSON**。
> `terminate` 目前会被核心丢弃（处置见 docs/agent-base-plan.md §1.3），不要依赖它结束整轮。

## 5. 沙箱环境与限制

| 项 | v1 现状 |
|---|---|
| 转译 | oxc 类型擦除（`ts_engine::compiler::transpile_ts_module`） |
| 运行时 | 进程内 `PureTsRuntime`（Boa），**不是** Node/Bun |
| 可用基础模块 | node 风格环境：`process`/`fs`/`path`/`os`/`crypto`/`url`/`util`/`timers`/`buffer`/`events`（`ts_engine/src/env/**`） |
| 模块解析 | **没有**——单文件自包含（§1） |
| 工作区可见性 | 通过 `api.workspace`（形态 A）或工厂参数（形态 B）拿到路径字符串；**路径沙箱由核心侧工具判定**，插件自行读写文件时不受核心沙箱保护，请自行校验 |
| 检查工具声明的超时 | 15 秒（`sandbox.rs:116`） |
| 执行工具的超时 | 由调用方给：当前 executor 传 **30 秒**（`runner/executor.rs:199`） |
| 钩子点位 | **v1 不支持**：沙箱只有 `inspect_plugin` / `call_tool` 两个入口；Rust 引擎尚未调用任何钩子（25 个点位是 TS 时代的产物，补在 M6） |
| 能力位 | `hookTimeoutMs` / `allowThirdPartyHooks` 等目前**只被解析、未被消费**（`plugins/manager.rs:101-110`）；不要据此设计插件 |

## 6. 版本与兼容

- **v1 = 本文**（随 TS 归档生效）。v1 的破坏性变更必须出新版本号并保留一个版本的兼容期。
- 新增**能力**只能加法：先加能力位（`PluginCapabilities`），再实现；未实现的能力位不得声明为 true。
- 插件发现与 id 规则：第三方插件 id 由加载器定为 `「scope:文件名」`（内置为 `builtin:<id>`）；
  `(builtin):` 虚拟路径**不会被送进沙箱**（`runner/executor.rs:190`）。

## 7. 最小可运行模板

`plugin.createTemplate` 生成的模板就是形态 B 的自包含文件；手工起步照抄这个即可：

```ts
export default {
  tools: [
    {
      name: 'count_lines',
      description: '统计某个文件的行数',
      parameters: { type: 'object', properties: { path: { type: 'string' } }, required: ['path'] },
      async execute(args: { path: string }) {
        const fs = require('fs')
        const text = fs.readFileSync(args.path, 'utf8')
        return { ok: true, output: `${args.path}: ${text.split('\n').length} 行` }
      },
    },
  ],
}
```

冒烟检查（不改核心代码就能验）：把文件放到工作区插件目录 → `plugin.list` 能看到工具 →
让模型调一次 → 结果回执里 `status == "success"`。

## 8. 待补齐（M6，不是 v1 的一部分）

1. **钩子点位**：25 个点位（`afterToolCall`/`beforeApproval`/`beforeTurn`…）由 Rust 引擎调用，
   经 `HookRunner` 端口进入沙箱；含成对约束、超时与熔断。
2. **技能/提示词注册**：让 `registerSkill`/`registerPrompt` 真正生效（或从 API 中删除——不许留空实现）。
3. **`terminate` 语义**：接进 `Termination::{ContinueTurn, EndTurn}`。
4. **多语言/WASM 插件**：作为新的 `PluginHost` 实现，不改本 SDK 的工具契约。
